# AI-Assisted Development

이 프로젝트는 Claude Code를 구현·디버깅 보조 도구로 사용했다. 연구 질문, 생물학적 가설,
검증 전략, 임상적 한계에 대한 판단은 프로젝트 저자가 정하고 검토했다. 이 문서는 그 역할
분담을 투명하게 밝힌다.

|---|---|
| 연구 질문 설정 | 사람 |

## AI를 어떻게 활용했는가

Claude Code는 다음을 지원했다:
- **코드 스캐폴딩**: KEGG flat file 파서, CSV 출력 유틸리티 등 반복적인 뼈대 코드 작성
- **리팩터링**: 저장소를 인터뷰용 포트폴리오 구조로 재구성하면서 경로 하드코딩 제거,
  숫자 접두사 파일명 간 import 문제 해결을 위한 공용 유틸리티 모듈 분리
- **반복적인 파싱 작업**: KEGG의 고정폭 텍스트 포맷, ClinVar의 탭 구분 대용량 파일 스트리밍
  처리 같은 정형화된 파싱 로직 작성
- **디버깅**: REMARK 필드 정규식 lookahead가 다음 항목까지 잘라먹는 버그, "테스트된 위치
  있음"과 "실제 대립유전자 보유"를 구분하지 못해 병원성 기록이 많은 유전자가 과대 집계되는
  버그 등을 찾고 수정
- **문서화 보조**: README, 방법론, 검증 전략 등 문서 초안 작성

## 사람의 검증

AI가 생성한 코드나 결과를 "실행이 성공했다"는 이유만으로 그대로 받아들이지 않았다. 다음
방법으로 결과를 검증했다(자세한 내용은 [`validation.md`](validation.md)):

- **원본 데이터 건수 대조**: KEGG 엔트리 수, 가족 rsid 합집합 크기(1,117,586개) 등 원본에서
  직접 셀 수 있는 값과 스크립트 출력이 일치하는지 확인
- **중간 산출물 점검**: 각 파이프라인 단계의 출력 CSV를 다음 단계에 넘기기 전에 건수·컬럼을
  직접 확인
- **알려진 생물학적 관계와 대조**: CFH↔보체계 질환 클러스터링, CFH 재창출 후보와 실제
  FDA 승인 보체억제제(Pegcetacoplan, Iptacopan, Danicopan) 일치, PGx 공통 마커(VKORC1,
  CYP3A5, UGT1A1)가 실제 CPIC/FDA 등재 마커인지 등을 수작업으로 대조
- **외부 데이터베이스 비교**: ClinVar와 KEGG라는 서로 다른 두 소스가 같은 유전자(CFH)를
  가리키는지 교차검증
- **육안 스팟 체크**: rs460897/rs1061170 보유자 목록처럼 구체적인 값을 직접 확인
- **리팩터링 후 재실행 검증**: 이번 저장소 재구성에서 모든 파이프라인 경로를 바꾼 뒤 스크립트를
  다시 실행해, 재구성 전 커밋에 있던 수치와 정확히 일치하는지 확인했다(69,546건 KEGG 관계,
  5,890건 재창출 후보, CFH 교차검증 2건 등 — 전부 재현됨)

## 책임 있는 사용(responsible use)

AI는 임상적 진단을 내리거나 약물을 처방하지 않았다. 이 저장소의 모든 "병원성 변이",
"약물유전체 마커", "재창출 후보" 표현은 데이터 파이프라인이 만들어낸 스크리닝 결과이며,
사람에 의한 최종 생물학적·임상적 판단을 대체하지 않는다. 실제 임상 적용 전에는 반드시
의사·약사·유전상담사와 상의해야 한다.
