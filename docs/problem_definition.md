# 데이터 분석 문제 정의

## 데이터를 고른 이유

KEGG(Kyoto Encyclopedia of Genes and Genomes)는 유전자·질병·신호전달경로·약물이 서로
어떻게 연결되는지를 정리해놓은 생물정보학 데이터베이스이고, 여기에 우리 가족의 실제
유전체(23andMe SNP) 데이터를 더하면 "교과서적인 생물학 지식"과 "실제 우리 가족의
데이터"를 같은 틀 안에서 다뤄볼 수 있다. 단순히 공개 데이터셋을 분석하는 것보다,
결과가 실제로 나 자신 및 가족과 관련이 있다는 점에서 데이터 정제·검증을 더 꼼꼼히
하게 되고, 각 분석 단계의 의미를 훨씬 구체적으로 체감할 수 있다는 점이 이 데이터를
고른 이유다.

## 오늘 풀 문제

1. KEGG의 원본 flat file(dgroup/disease/drug/network/variant, 총 5개)은 사람이 읽기
   위한 텍스트 포맷이라 분석에 바로 쓸 수 없다 — 이걸 어떻게 관계형 테이블로 구조화하고,
   엔트리 간에 실제로 어떤 관계(질병-유전자-경로-약물)가 몇 건이나 있는지 파악할 것인가.
2. 가족의 SNP 원시 데이터는 그 자체로는 아무 의미가 없는 rsid·genotype 나열일 뿐이다 —
   이걸 KEGG나 ClinVar 같은 질병·임상 데이터베이스와 실제로 연결해서, "이 가족이 어떤
   유전자 영역에 어떤 변이를 실제로 보유하고 있는지"를 근거 있게 확인할 수 있는가.
3. 확인된 유전자/변이가 그저 "발견"에 그치지 않고, 관련 질병·경로·약물(재창출 후보,
   약물유전체 반응)까지 자동으로 이어지는 하나의 분석 파이프라인으로 만들 수 있는가.

## 오늘 데이터에서 확인해볼 것

1. KEGG 5개 파일 각각의 필드 구성과 엔트리 수, 그리고 엔트리끼리 서로를 참조하는
   식별자(예: `[DR:D00001]`, bare `D07668`)가 실제로 몇 건이나 존재하는지.
2. 가족 SNP 데이터(Father/Mother/Child 1/2/3)의 기본 품질 — 총 SNP 수, 결측률,
   이형접합률이 구성원 간에 비슷한지, 다르다면 왜 다른지(칩 버전 차이 등).
3. 가족 SNP의 rsid가 KEGG의 유전자·변이 정보, 그리고 외부 임상 데이터베이스(ClinVar)와
   실제로 join 가능한 공통 키를 갖는지 — 그리고 매칭됐을 때 그 결과를 얼마나 신뢰할 수
   있는지(리뷰 신뢰도, 독립 데이터베이스 간 교차검증).
